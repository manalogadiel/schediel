# Phase 6 local image import implementation

Goal: bounded local still-image preparation → on-device OCR → conservative, evidence-backed candidates → explicit resolution → shared transactional review. Implements SCHEDULER_SPEC.md §§8,16 and CONTRACTS.md §4. No cloud path, database writes, alerts, router or permission configuration in this feature.

## University table support (October 20)

The local adapter recognizes the six-column university format using validated OCR regions, independent of OCR reading order. It joins wrapped code/title/instructor/time/room lines, separates merged Code + Description text and emits one weekly candidate per meeting. Units/Section never become Notes. Character geometry distinguishes a narrow, separated slash misread as T/I/1 from real leading room characters; without that geometry no such character is removed. Missing course anchors cannot absorb a neighboring course's description.

Description → Title; Instructor → Professor; Code → Subtitle; schedule suffix → Room/location. Notes and alerts remain absent. A shared date/repeat form offers One time and Weekly. One time adds each meeting once on its first matching weekday from the chosen starting date; Weekly additionally requires term boundaries. Individual Resolve fields can override the repeat mode. Source-zone confirmation and an association check remain required. Existing edits are preserved. The review selects the existing School category and still permits changes before the transactional Add command. Generic posters and unknown layouts retain the conservative unresolved-field flow. Textbox labels are drawn above their control, outside its fill/border, with accessible input labels.

The provided image was recognized on the Android phone, then checked locally against all fourteen meeting mappings. Its source image/OCR diagnostics remain untracked/ignored and are never uploaded or bundled into the normal app. OCR can still misread instructor spelling/punctuation; review against the source remains required. No model retraining or cloud processing is claimed.

## Tracer bullets (test first, observe RED, implement, GREEN)

1. `domain/image_preparation.dart`, `data/local_image_preparer.dart`: actual-signature admission (10 MiB/40Mpx before decode), static JPEG/PNG/WebP/GIF/BMP and single-page TIFF; Android 9+ HEIC/AVIF conversion checks headers and requests bounded decode on a serial background task queue; isolate orientation/crop/rotation, pixel-only output ≤5 MiB/12Mpx/4096 per dimension. Tests: spoofed/corrupt/animated/bomb inputs, orientation, exact crop/rotate, stripped metadata, normalization limits.
2. `domain/ocr_document.dart`, `domain/image_candidate.dart`, `domain/conservative_parser.dart`: bounded OCR and ≤100 candidates, ISO/text-month full dates, date-only posters, explicit clocks, weekly weekdays needing term context, exact spans/validated normalized regions and per-field provenance. Tests: missing year/order/AMPM/zone/title/association, overflow, hostile plain text.
3. `data/mlkit_ocr.dart`, `application/image_import_controller.dart`: injectable adapter/picker/preparer, close MLKit per run, decode its nullable native geometry without discarding text, distinct failure states, revisions invalidate stale pick/prep/OCR results, recoverable errors retain edits, own transient cleanup. Tests: mocked native channel through real normalization/parser pipeline, cancellation, retries, stale completion and disposal.
4. `presentation/image_import_screen.dart`, `image_crop_screen.dart`, `candidate_resolution_screen.dart`: gallery/optional camera only on tap, exact region preview with real pixel crop/quarter-turn rotation, removable source, editable unresolved values and explicit end/association decisions; pass only resolved `ImportEntry` drafts to `ImportReviewScreen`. Alerts/categories/duplicates/commit belong only to shared review. Widget tests cover unresolved form, source removal, cancel, preview handoff and no pre-review storage.

## Verification and release limits

Run `flutter analyze lib/features/image_import test/features/image_import` and `flutter test test/features/image_import` without editing other agents' paths. Windows mock-channel tests are not evidence of native OCR accuracy, gallery/camera permissions, mobile decoding performance or Android/iOS integration. Device QA remains required. Complex tables always carry a partial-layout warning; no completeness/confidence claim.
